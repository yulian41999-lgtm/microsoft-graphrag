## 可从日志补算

历史评分 token 可合并 scores 与 repair 调用日志，失败格式响应也计入，reused 记录不是新 API 响应。历史 QA 核心耗时可累加逐题 latency；清单起止时间差可给出不含完整初始化的历史日历区间。

logs/indexing-engine.log 末尾包含模型累计统计：生成模型 28818 次成功响应（含 2357 缓存响应），输入 25523351、输出 14616394、总计 40139745 tokens；嵌入模型输入及总计 9289677 tokens。原日志为库层聚合且含缓存，不能称为当次实际付费或已保存 API 响应数；已核对当前 DefaultMetricsProcessor 从 response.usage 累加 token，但不能将含缓存和跨启动的聚合冒称当次新增 API 消耗。保存聚合原始字段并明确范围，不对缓存费用推算。

## 需要新增记录并重跑

历史 QA 的 generation_usage 为 null，无法恢复服务端实际 token；旧裁判日志无完整调用计时，不能补造耗时。故统一重跑两组问答及四指标评分。生成均采用非流式响应保存服务端 usage，沿用相同模型、温度 0、输出上限 4096 和已有提示词。裁判两组统一 8192 输出上限、240 秒超时，保留原有公式和验证规则。

## 图模式边界

原文组保留原 Local 混合检索比例；仅图组删除构建器中的全部原文块，保留原有预算比例，原文预算空置。两组最大上下文预算均为 10000 个 GraphRAG tokenizer tokens，实体 15、关系 20、社区比例 0.1。预算相同不表示实际长度相同；图模式是固定图预算、删除原文块的消融对照，报告另行核验两组实际图记录是否一致。

实体与关系描述来自历史抽取及描述合并；社区报告是历史生成的派生摘要，可能含原文引语，不能作为独立原始证据。仅图组允许这些已有图记录，不读取原文正文入生成请求。生成请求和实际上下文逐题保存。原始语料、金标准及索引不变，不运行构图或索引入口。

## 启动与缓存

两组使用新进程与新检索引擎，生成和查询嵌入均绕过调用缓存，顺序运行，共享已就绪的模型服务；不重启服务，不宣称清空操作系统或服务端内部前缀缓存。初次 original 运行是记录器验证，单独保存其消耗，不纳入最终两组。正式组放在 final_original 和 final_graph_only。
