## 主要结论

两项目当前配置均表现为：仅图回答减少 token，同时总体四项质量均下降。HippoRAG2 问答总 token 减少约 31.9%，GraphRAG 问答总 token（含查询嵌入）减少约 53.6%；答案正确性分别下降约 0.0730 与 0.0731。它们是各项目内的观察，不能据此断言哪一种图方法更优。

## 模型、检索与对照条件

- 共同生成／裁判模型：`qwen3.8-27B-raw`；共同嵌入模型族：BGE-M3，1024 维 dense。HippoRAG2 固定的上游 revision 见 `hipporag_local/upstream_revision.txt`，GraphRAG 安装版为 3.3.0。
- HippoRAG2：分块上限 512 BGE tokens、重叠 64；检索候选 20、回答最多 5 份资料、上下文预算 3072 BGE tokens；生成输出上限 2048。原文模式提交检索原文；仅图模式提交最多 5 个历史事实种子三元组，不是完整邻域或多跳子图。
- GraphRAG：分块 800、重叠 120 个 o200k tokens；Local 实体 15、关系 20、上下文上限 10000 个库内 tokenizer tokens；原文预算比例 0.65、社区比例 0.1；生成输出上限 4096。原文模式为原文与图混合；仅图模式删除原文块，原文预算空置，保留相同图记录。
- HippoRAG2 两轮事实种子 14/15 题相同，F008 存在 LLM 筛选波动，图模式另加三元组解释提示；GraphRAG 两组所有题的实体、关系、报告及 claims 记录完全一致。两套实验对表示方式的控制强度不同。
- HippoRAG2 初次裁判上限 3072、超时 90 秒，仅对失败指标用 8192／240 秒恢复并保留成功结果；GraphRAG 两组裁判统一 8192／240 秒。指标公式及四指标名称一致，裁判输出预算与恢复过程并未跨项目统一。
- HippoRAG2 使用独立空 LLM 缓存；GraphRAG 绕过生成与查询嵌入客户端缓存。两者均使用新进程，不能控制服务端前缀缓存、操作系统缓存及其他任务负载。

因此下列跨项目数值为“各自现有配置的描述性并列”，不是同输入预算、同输出上限、同检索调用数量的严格算法评测。BGE 与 o200k 的 token 预算也不能直接等同。

### 成本解释

- HippoRAG2 问答 token 包含 LLM 检索重排及生成，BGE 在本地计算；GraphRAG 问答合计包含生成和查询嵌入 API。不能把 GraphRAG 纯生成 token 直接和 HippoRAG2 全问答 token 比较。
- HippoRAG2 核心计时从创建检索对象开始，包含部分模型／索引加载和检索准备；GraphRAG 核心时间为逐题检索加生成累计，不含引擎初始化与题间写盘。这两列不具备跨系统严格可比性。
- GraphRAG 原文组初始化／写盘约 48.1 秒，仅图约 7.5 秒；历史审计磁盘读取与原文运行有重叠。整体日历时间差不能作为稳定加速比。两项目也共享模型服务，独立运行的调用可能互相影响。
- 评分成本是实验评测投入，不应当作每次业务回答的必需成本。模型使用量优先取服务端 usage，格式失败和重试也计入对应阶段。HippoRAG2 原文裁判共 96 次响应，已包含失败和恢复，不再另加 repair_cost 子项。
- 当前正式组的服务端 usage 均有记录。API 零调用不代表本地 BGE 无计算；本地计算 token／独立耗时未完整记录，资源及人民币费用不纳入。GraphRAG 前置记录器验证的 15 次生成另列在其 summary.json，不混入正式两组或跨系统合计。
